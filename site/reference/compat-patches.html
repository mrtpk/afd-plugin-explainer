Reference: compat patches

AdvancedReferenceabout 5 min read

Code version: afd-plugin @ 7452d52 · 2026-10-27 · vLLM @ ced6857

In one sentence

This table lists every patch in afd_plugin/compat/patches/, its vLLM target at the pinned commit, its install mechanism, when it is active, and what it changes.

How to read this table#

Each row is one replaced function. The vLLM target is the function the patch stands in for, at the pinned vLLM commit (ced6857). The install column says where and how AFD installs the patch and what gates it. The active when column says which configs the patch actually changes; the others see native behavior. Every GPU patch is behind the version gate is_target_vllm_compatible (afd_plugin/compat/vllm.py:53-68). The concept page is Compat patches: how AFD changes vLLM without editing it.

NPU-gated patches#

These two modules install at import time but only change behavior for async-DP configs, which are NPU only. On GPU, async_dp must be false, so they run as transparent re-implementations (afd_plugin/config.py:303-308).

What is not patched#

AFD does not patch the API server, the scheduler, the sampler or the attention and KV kernels. The attention runner wraps native methods instead of replacing them (afd_plugin/v1/worker/attention_model_runner_v2.py:569-595), and sampling stays native (vllm:vllm/v1/worker/gpu/model_runner.py:2048-2050).

  • Dual-batch overlap (DBO): two stages per stepDBO splits one step into exactly two stages. While one stage waits on the FFN side, the other computes attention, so the two roles stay busy. AFD adds a yield op and scoped patches for DP1.
