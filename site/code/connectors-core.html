connectors/base.py, factory.py, metadata.py: the connector core

IntermediateCode mapabout 4 min read

Code version: afd-plugin @ 7452d52 · 2026-10-27 · vLLM @ ced6857

Before you read

This page uses ideas from these pages:

  • The connector contract: the Attention/FFN transport Intermediate

In one sentence

Three files form the connector core: base.py (the contract), factory.py (name to class) and metadata.py (the shared data objects).

Purpose#

These files hold the parts every connector shares. The contract and the factory are explained on the The connector contract: the Attention/FFN transport page; this page maps the three files and reads the metadata objects and the factory loader.

Where it sits#

Who calls it#

The factory builds a connector for a runner. The FFN runner calls create_connector at construction (afd_plugin/v1/worker/ffn_model_runner.py:80-85); the attention runner does the same. The model wrappers build the metadata objects for each transfer (afd_plugin/model_executor/models/deepseek_v2.py:140-145).

What it calls#

base.py reads the AFD config helper connector_extra_config_from_source (afd_plugin/connectors/base.py:105-107). factory.py imports the connector module lazily with importlib (afd_plugin/connectors/factory.py:38-45). metadata.py encodes the control payload with json (afd_plugin/connectors/metadata.py:344-346).

Walk through the main methods#

AFDTransferMetadata: the per-transfer record#

This dataclass describes one layer-and-stage transfer. It validates its lengths and derives the total token count (afd_plugin/connectors/metadata.py:171-200).

  1. Line 188-190. The fields: layer_idx, stage_idx, and the per-peer seq_lens list.
  2. Line 192-196. __post_init__ rejects an empty list and any non-positive length.
  3. Line 198-200. total_tokens is the sum of the lengths; it is the expected leading dimension.

Two class methods build the attention form (one length) and the FFN form (a list of lengths) (afd_plugin/connectors/metadata.py:202-228). The shape check is validate_tensor_shape (afd_plugin/connectors/metadata.py:230-231).

encode_control_payload: the wire format#

The control payload is serialized to compact JSON, with only the fields the FFN side reads back (afd_plugin/connectors/metadata.py:320-346).

  1. Line 329-335. One entry per stage: the per-DP-rank token list and its max.
  2. Line 337-343. The graph-capture, warm-up, replay and profile flags.
  3. Line 344-346. json.dumps with sorted keys and no spaces. The The control plane: DP metadata once per step page reads the send and receive.

AFDConnectorFactory: name to class#

The factory keeps a registry of loaders. register_connector stores a loader that imports the module lazily (afd_plugin/connectors/factory.py:26-47); create_connector looks the name up, resolves the role rank, and builds the instance (afd_plugin/connectors/factory.py:49-68).

Three connectors are registered at import time; an unknown name raises (afd_plugin/connectors/factory.py:58-59, afd_plugin/connectors/factory.py:88-102).

Check yourself#

  1. 1
    Which file holds the shared metadata dataclasses?
    easy
    Show answer

    connectors/metadata.py. It defines AFDDPMetadata, AFDControlPayload, AFDTransferMetadata and the transfer payloads (afd_plugin/connectors/metadata.py:23, afd_plugin/connectors/metadata.py:171).

  2. 2
    How does the factory load a connector class?
    medium
    Show answer

    Lazily. register_connector stores a loader that imports the module with importlib and checks the subclass only when the name is first used (afd_plugin/connectors/factory.py:38-47).

  3. 3
    What is total_tokens, and where is it checked?
    hard
    Show answer

    It is the sum of the per-peer seq_lens (afd_plugin/connectors/metadata.py:198-200). validate_tensor_shape checks that a tensor's leading dimension equals it (afd_plugin/connectors/metadata.py:230-231).
