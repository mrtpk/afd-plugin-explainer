afd_plugin/config.py: the AFD config schema and parser

IntermediateCode mapabout 4 min read + 1 min deep dives

Code version: afd-plugin @ 7452d52 · 2026-10-27 · vLLM @ ced6857

Before you read

This page uses ideas from these pages:

  • AFD configuration: additional_config["afd"] Intermediate

In one sentence

This module defines AFDConfig and the functions that parse and validate additional_config["afd"], with no vLLM or CUDA import.

Purpose#

The module turns a raw mapping into a validated AFDConfig. It is CPU-safe, so local tests parse a config without vLLM.

Filesafd_plugin/config.py (370 lines), config_utils.py (75 lines), afd_plugin/envs.py (27 lines).
Main classAFDConfig, a frozen dataclass (afd_plugin/config.py:41-73).
Runs inAny process (CPU), during config build and worker init. No vLLM import at module load.
Called byThe config patch (afd_plugin/compat/patches/config_validation.py:23), the validation module (afd_plugin/validation.py:12-17), and the connector factory.
CallsThe coercers in config_utils.py (afd_plugin/config.py:13-15).
Not in this filePer-connector option parsing (in each connector), worker selection (in validation.py), and the vLLM config field itself.

Where it sits#

Who calls it#

Every part that needs the AFD config parses it here. The config patch parses it to decide the worker and the NPU path (afd_plugin/compat/patches/config_validation.py:160-172). The runtime validators parse it with an expected role (afd_plugin/validation.py:93).

What it calls#

It calls the three coercers in config_utils.py for the typed fields (afd_plugin/config.py:147-174). It imports validate_p2p_topology lazily, only for the P2P connector (afd_plugin/config.py:335-338).

Walk through the main methods#

AFDConfig and its aliases#

The dataclass is frozen, so a config cannot change after it is built. Each old afd_* name is a read-only property that returns the short field (afd_plugin/config.py:75-89).

_normalize_mapping#

This function does the rename, the split and the coercion in one pass.

  1. Line 128. It maps the key through _ALIASES, so an alias becomes its short name.
  2. Lines 129-133. It pulls connector_extra_config aside and checks it is a mapping.
  3. Lines 134-139. An unknown field raises, with a message that points to connector_extra_config.
  4. Lines 140-144. An alias and its canonical key together raise a duplicate error.

After the loop, it coerces the boolean and integer fields (afd_plugin/config.py:147-174).

validate_afd_config#

The validator runs on the built config. It raises a clear error for each broken rule (afd_plugin/config.py:311-350). For the P2P connector it also checks the topology (afd_plugin/config.py:335-338).

config_utils.coerce_extra_int#

The integer coercer rejects a bool or a float before it calls int(), so a wrong type cannot be truncated silently (afd_plugin/config_utils.py:35-45).

Check yourself#

  1. 1
    Why is AFDConfig a frozen dataclass?
    easy
    Show answer

    So a config cannot change after it is built (afd_plugin/config.py:41). The old names are read-only properties (afd_plugin/config.py:75-89).

  2. 2
    Which function parses the config without validating it, and why?
    medium
    Show answer

    is_afd_async_dp. It is a lightweight selector for import-time async-DP patches, so it parses with validate=False (afd_plugin/config.py:295-308).

  3. 3
    What does _normalize_mapping do with a key it does not know?
    medium
    Show answer

    It raises ValueError and points to connector_extra_config for connector-specific values (afd_plugin/config.py:134-139).

  4. 4
    A caller passes "num_ffn_ranks": True. Where and why does this fail?
    hard
    Show answer

    In coerce_extra_int: it rejects a bool before calling int(), so the value does not become 1 (afd_plugin/config_utils.py:38-39). The integer fields use this coercer (afd_plugin/config.py:153-162).
