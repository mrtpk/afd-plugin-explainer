Tour: One decode step

AdvancedGuided toursabout 7 min read + 1 min deep dives

Code version: afd-plugin @ 7452d52 · 2026-10-27 · vLLM @ ced6857

Before you read

This page uses ideas from these pages:

  • Tour: Life of a request Intermediate
  • Dual-batch overlap (DBO): two stages per step Advanced

In one sentence

Follow one decode step on 2A2F with DBO and FULL_DECODE_ONLY graphs. The control plane publishes once; each layer runs two stages.

The idea#

One decode step produces one new token per request. On AFD, the attention side runs the step and the FFN side answers each layer. With DBO, each layer runs two stages that overlap. With graphs, both sides replay instead of running eager.

This tour follows the graph recipe: 2A2F, DP1, TP2, DBO on, FULL_DECODE_ONLY (recipe/gpu/P2pNcclAFDConnector/deepseek_v2_lite/prefill_decode_colocation/2a2f_graph_dbo_dp1tp2.sh:7-29). Rank A0 maps to F0 and A1 to F1 (afd_plugin/distributed/topology.py:135-136).

Keep the two frequencies apart. The control plane publishes DP metadata once per step, before the layer loop. The data plane sends tensors once per layer and stage. Sampling runs once per step, after the last layer.

The picture#

Read the top panel as the once-per-step work and the bottom panel as the per-layer, per-stage work. The visual below steps through the same send, yield, compute and receive events.

Simplified

The visual shows the event order, not real timing. It leaves out the control-plane publish before the loop, the graph replay, the per-peer split, and sampling. The stops give those, with citations.

1The scheduler builds one step#

The attention server's EngineCore and scheduler build one step, then the executor runs it (vllm:vllm/v1/engine/core.py:600-601). This is native vLLM. The FFN server has no such loop; it is connector-driven (afd_plugin/v1/worker/ffn_worker.py:32-38).

2The runner wraps native execute_model#

The executor calls the AFD runner's execute_model. It wraps the native method in an AFD execution context, then delegates (afd_plugin/v1/worker/attention_model_runner_v2.py:569-595).

Native code still does the request, attention and KV work. The wrapper adds AFD state around it. See The attention runtime: a seam over Model Runner V2.

3The AFD context installs the provider and the replay hook#

The context scopes four things: the DP1 DBO dispatch seam, the FULL replay hook, the ubatch prepare seam, and the metadata provider (afd_plugin/v1/worker/attention_model_runner_v2.py:340-349).

The replay hook is used only in FULL_DECODE_ONLY mode with a graph manager (afd_plugin/v1/worker/attention_model_runner_v2.py:323-327). See CUDA graphs in AFD: FULL_DECODE_ONLY on both roles.

4The control plane publishes DP metadata once#

Before the layer loop, the attention side publishes the DP metadata. With DBO, the ubatch prepare seam sends it after it slices the step into two stages (afd_plugin/v1/worker/attention_model_runner_v2.py:153-157).

That call updates the local control state and sends one payload (afd_plugin/v1/worker/attention_metadata.py:115-116). It is the first thing that crosses the connector each step. See The control plane: DP metadata once per step.

Deep dive

The two publish paths, both once per step

There are two code paths to the same publish, chosen by whether the step uses DBO. Both run once per step, before the layer loop.

  1. With DBO. The ubatch prepare seam calls send_dp_metadata after it slices the step into two stages (afd_plugin/v1/worker/attention_model_runner_v2.py:153-157).
  2. Without ubatching. The metadata provider calls it from install_afd_metadata_on_forward_context (afd_plugin/v1/worker/attention_metadata.py:252-257).

The FFN side waits for exactly one payload per step either way (afd_plugin/v1/worker/ffn_worker.py:176). A per-step call must not be folded into the per-layer sequence. The payload carries the per-stage token counts that set the tensor shapes. See Data on the wire: tensors per layer and stage.

5The attention side replays its graph#

For a pure-decode step, native FULL replay runs. The replay hook publishes one padded control payload just before the replay (afd_plugin/v1/worker/attention_model_runner_v2.py:286-303). For a DBO step with two stages, the prepare seam already sent the full two-stage payload, so the hook asserts and delegates (afd_plugin/v1/worker/attention_model_runner_v2.py:275-280).

6Per layer and stage: send, yield, the other stage#

Inside each layer, the proxy sends its hidden states, yields, then receives. The yield lets the other stage run while this one waits (afd_plugin/model_executor/models/deepseek_v2.py:146-158).

This runs once per layer and once per stage. With DBO there are two stages per layer. See Dual-batch overlap (DBO): two stages per step.

7The FFN side receives one DP-metadata payload per step#

The FFN server loop blocks on the control plane for exactly one payload per step (afd_plugin/v1/worker/ffn_worker.py:176), then dispatches to execute or capture (afd_plugin/v1/worker/ffn_worker.py:182-196).

So the control plane runs once per step on the FFN side too, matching the attention side.

8The FFN side looks up and replays its graph#

The FFN runner builds the FFN graph key from the DP metadata and replays the stored graph for a pure-decode step (afd_plugin/v1/worker/ffn_model_runner.py:166-177). If no graph matches the key, it runs eager instead.

See CUDA graphs in AFD: FULL_DECODE_ONLY on both roles.

9Per layer and stage: recv, compute, send#

The eager path, _ffn_forward, loops over layers and stages. For each pair it receives the hidden states, runs the FFN or MoE compute, and sends the result back (afd_plugin/v1/worker/ffn_model_runner.py:222-269).

When the FFN side replays a graph, this same work is recorded in the graph instead of run step by step. See The FFN runtime: a connector-driven server loop.

10After the last layer: sample, then output#

After the forward pass, the worker makes a separate native call, sample_tokens (vllm:vllm/v1/worker/gpu_worker.py:1142-1147). Native Model Runner V2 computes the logits and samples there (vllm:vllm/v1/worker/gpu/model_runner.py:2048-2050). The AFD attention runner does not override this method, so it samples natively.

The FFN runner has no sampler; its sample_tokens raises (afd_plugin/v1/worker/ffn_model_runner.py:405-406). So sampling runs once per step, on the attention side. The step is done; the next step repeats the whole path.

What can go wrong#

  • Folding the per-step publish into the layer loop. The control plane publishes once, before the layers; it does not publish again inside the loop (afd_plugin/v1/worker/attention_metadata.py:115-116).
  • A shape that no captured graph covers. The FFN side runs that step eager instead of replaying (afd_plugin/v1/worker/cuda_graph.py:148-150).
  • A step too small for DBO. A step below the threshold runs as one stage, with no overlap (vllm:vllm/v1/worker/ubatch_utils.py:144-149).
  • Expecting the FFN side to sample. It never does; its sample_tokens raises (afd_plugin/v1/worker/ffn_model_runner.py:405-406).

Why it matters. One step has one control-plane publish, then every layer and stage of send and receive, then one sampling call. The frequencies must not be mixed, or the two roles fall out of step.

Check yourself#

  1. 1
    How many times does the control plane publish per step?
    easy
    Show answer

    Once, before the layer loop. The attention side sends one DP-metadata payload (afd_plugin/v1/worker/attention_metadata.py:115-116); the FFN loop receives one (afd_plugin/v1/worker/ffn_worker.py:176).

  2. 2
    What does the FFN runner do when a graph matches the key?
    easy
    Show answer

    It calls graph.replay() and returns, instead of running the layers eager (afd_plugin/v1/worker/ffn_model_runner.py:175-177).

  3. 3
    In a DBO step, why does the FULL replay hook not send a new control payload?
    medium
    Show answer

    Because the ubatch prepare seam already sent the full two-stage payload. The hook asserts the staged metadata and delegates to the native replay (afd_plugin/v1/worker/attention_model_runner_v2.py:275-280).

  4. 4
    Which side samples the token, and when?
    medium
    Show answer

    The attention side, once per step, after the last layer. The AFD runner inherits the native sample_tokens (vllm:vllm/v1/worker/gpu/model_runner.py:2048-2050); the FFN runner's raises (afd_plugin/v1/worker/ffn_model_runner.py:405-406).

  5. 5
    List the per-stage data-plane calls for one layer, in order, across both roles.
    hard
    Show answer

    Attention send_attn_output (afd_plugin/model_executor/models/deepseek_v2.py:146); DBO yield; FFN recv_attn_output (afd_plugin/v1/worker/ffn_model_runner.py:236); FFN compute; FFN send_ffn_output (afd_plugin/v1/worker/ffn_model_runner.py:268); attention recv_ffn_output (afd_plugin/model_executor/models/deepseek_v2.py:155). This runs for each of the two stages.
