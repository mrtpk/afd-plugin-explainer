Tuning: the knobs the repo exposes

AdvancedAFD conceptsabout 5 min read + 2 min deep dives

Code version: afd-plugin @ 7452d52 · 2026-10-27 · vLLM @ ced6857

Before you read

This page uses ideas from these pages:

  • Deployment topologies: how to place the roles Intermediate

In one sentence

AFD exposes a small set of knobs. This page lists each one, where the code reads it, and the only numbers the repository states for it.

The idea#

Tuning AFD means three things: shape the split and the overlap for throughput, set the timeouts and gate for reliable startup, and measure with the profiler and benchmark tools. The repository gives example values for some knobs and says to tune them for the workload. This page uses only numbers the code or the READMEs state.

An everyday comparison. Think of the knobs on an audio mixer. Each one changes one thing, and the factory marks are a starting point, not the final mix. The comparison stops at the meters: here the meters are the profiler and the benchmark, not your ear.

No invented speedups

This page does not claim a speedup for any setting. The recipe values (DBO 2/12, capture size 64) are example values the READMEs say to tune (recipe/gpu/P2pNcclAFDConnector/deepseek_v2_lite/README.md:140-143, recipe/gpu/P2pNcclAFDConnector/deepseek_v2_lite/README.md:154-157).

The picture#

Read the three panels as three goals. Panel 1 shapes throughput; panel 2 keeps startup reliable; panel 3 measures. Each card gives the key or flag and the file where the code reads it.

In the code#

Step 1: The A:F rank ratio#

The attention ranks must be at least the FFN ranks. The P2P topology check raises when A < F (afd_plugin/distributed/topology.py:52-58). Within that rule you choose the counts and the DP/TP split per role (afd_plugin/validation.py:107-117). See Deployment topologies: how to place the roles.

Step 2: DBO thresholds#

DBO microbatches a step when the token count passes a threshold. The recipes set a low decode threshold 2 and prefill threshold 12 (recipe/gpu/P2pNcclAFDConnector/deepseek_v2_lite/prefill_decode_colocation/2a2f_graph_dbo_dp1tp2.sh:24-25). The vLLM defaults are higher: 32 for decode and 512 for prefill (vllm:vllm/config/parallel.py:227, vllm:vllm/config/parallel.py:232).

vLLM reads these thresholds per step to decide whether to microbatch (vllm:vllm/v1/worker/ubatch_utils.py:141-149). AFD requires exactly two microbatches when DBO is on (afd_plugin/validation.py:126-131). See Dual-batch overlap (DBO): two stages per step.

Step 3: CUDA graph capture size#

The graph variants set --max-cudagraph-capture-size and the cudagraph_capture_sizes list together, with cudagraph_mode: FULL_DECODE_ONLY (recipe/gpu/P2pNcclAFDConnector/deepseek_v2_lite/prefill_decode_colocation/2a2f_graph_dbo_dp1tp2.sh:26-29).

On GPU, AFD allows only FULL_DECODE_ONLY (afd_plugin/v1/worker/cuda_graph.py:20-21). The README says to set --max-cudagraph-capture-size and cudagraph_capture_sizes together, based on the batch sizes and GPU memory (recipe/gpu/P2pNcclAFDConnector/deepseek_v2_lite/README.md:154-157). See CUDA graphs in AFD: FULL_DECODE_ONLY on both roles.

Step 4: The group timeout#

afd_process_group_timeout_s sets how long the world process-group rendezvous waits; the default is 120 seconds (afd_plugin/config.py:70). The P2P connector reads it when it builds the world group (afd_plugin/connectors/gpu/p2p.py:275). The config comment says the right value depends on rank count, placement and model size, so it is left to the caller (afd_plugin/config.py:67-70).

Step 5: Gate placement#

compute_gate_on_attention moves the MoE gate to the attention side. When it is on, the FFN side runs only the expert layers (afd_plugin/v1/worker/ffn_model_runner.py:211-215). It defaults to false (afd_plugin/config.py:66). Not every model allows it: the Qwen3-MoE wrapper requires it to be false (afd_plugin/model_executor/models/qwen3_moe.py:84-87). See The MoE handoff: where the gate runs.

Deep dive#

Deep dive

BATCH_SIZE_FACTOR: the NPU CAM receive capacity

On an Ascend NPU, BATCH_SIZE_FACTOR multiplies the CAM receive capacity. The base is 262144 tokens; the factor is applied with native float rounding, default 1 (afd_plugin/validation.py:45-54). The async FFN graph capacity check uses the same figure (afd_plugin/compat/npu/feature_validation.py:245-249). This knob matters only on NPU; see Ascend NPU overview: the same contract, different transports.

Deep dive

The profiler

The plugin owns a torch profiler for each GPU runner role, enabled by environment variables with the prefix AFD_GPU_ATTENTION_PROFILER or AFD_GPU_FFN_PROFILER. The profiler is off until you set ..._ENABLE (afd_plugin/compat/profiler.py:46-61). Only then does the plugin build a torch profiler with the schedule from the other variables (afd_plugin/compat/profiler.py:64-96). The trace directory falls back to VLLM_TORCH_PROFILER_DIR, then to a per-role default (afd_plugin/compat/profiler.py:131-132). The NPU profiler is the same shape with one extra setting, ..._WITH_STACK (afd_plugin/compat/npu/profiler.py:52-70). The Environment variables reference page lists every profiler variable.

Deep dive

The routing simulator

For controlled MoE benchmarks, the plugin registers a deterministic routing strategy, afd_balanced (afd_plugin/model_executor/routing_simulator.py:166-171). Select it with vLLM's VLLM_MOE_ROUTING_SIMULATION_STRATEGY (afd_plugin/model_executor/routing_simulator.py:5-8). It returns uniform weights and deterministic expert ids from a fixed seed 1024 (afd_plugin/model_executor/routing_simulator.py:28). The optional AFD_BENCHMARK_FORCE_LB_TOPN_PER_RANK limits the local expert pool per EP rank; 0 selects all local experts (afd_plugin/model_executor/routing_simulator.py:125-127).

The simulator changes model outputs

The strategy replaces real routing with a synthetic cycle, so it changes model outputs (afd_plugin/model_executor/routing_simulator.py:10-11). Use it only for benchmark and profiling runs, not for serving.

Deep dive

The benchmark tools and the result images

The repository ships a benchmark harness under tools/benchmarks/. The request_generator.sh script drives load against a running server; it wraps vllm bench serve and takes every knob as an environment variable (tools/benchmarks/request_generator.sh:44-57). The decode_bench_server.sh script starts a 2A2F decode-only stand that fakes out prefill (tools/benchmarks/decode_bench_server.sh:4-20). For a Kubernetes run, the repository ships a run-vllm-bench-k8s contributor skill (.agents/skills/run-vllm-bench-k8s/SKILL.md:1-6).

The NPU recipes include result images with their own captions. The CAMP2p recipe reports DeepSeek-V3.2 decode throughput per die at 16K and 32K (recipe/npu/CAMP2pAFDConnector/deepseek_v3_2/README.md:365, recipe/npu/CAMP2pAFDConnector/deepseek_v3_2/README.md:373); the async recipe reports a text-matched median TTFT comparison (recipe/npu/CAMAsyncAFDConnector/deepseek_v3_2/README.md:432). These numbers are from older runtimes, so this page does not restate them as current results. See Ascend NPU overview: the same contract, different transports.

What can go wrong#

Simplified

This page lists the knobs the repository exposes. It does not tune them for you; the right values depend on the model, the hardware and the workload, as the READMEs say.

  • DBO on without two microbatches. AFD requires exactly two microbatches when DBO is on, and raises otherwise (afd_plugin/validation.py:126-131).
  • A graph mode other than FULL_DECODE_ONLY on GPU. The GPU runner accepts only FULL_DECODE_ONLY (afd_plugin/v1/worker/cuda_graph.py:20-21).
  • A timeout too short for the placement. The rendezvous fails when the world group does not form in time (afd_plugin/connectors/gpu/p2p.py:275).
  • The routing simulator left on for serving. It changes model outputs, so it gives wrong answers outside a benchmark (afd_plugin/model_executor/routing_simulator.py:10-11).

Why it matters. The knobs trade throughput, memory and startup time. The repository gives example values and the read sites; the right values come from measuring your own workload.

Check yourself#

  1. 1
    What DBO thresholds do the recipes set, and how do they compare with the vLLM defaults?

    Show answer

    The recipes set decode 2 and prefill 12 (recipe/gpu/P2pNcclAFDConnector/deepseek_v2_lite/prefill_decode_colocation/2a2f_graph_dbo_dp1tp2.sh:24-25). The vLLM defaults are higher, 32 and 512 (vllm:vllm/config/parallel.py:227, vllm:vllm/config/parallel.py:232).

  2. 2
    Is the profiler on by default?
    easy
    Show answer

    No. Each role's profiler is off until you set its ..._ENABLE variable (afd_plugin/compat/profiler.py:46-61).

  3. 3
    What does compute_gate_on_attention change, and which model forbids it?
    medium
    Show answer

    When on, the FFN side runs only the expert layers, because the attention side computes the gate (afd_plugin/v1/worker/ffn_model_runner.py:211-215). The Qwen3-MoE wrapper requires it to be false (afd_plugin/model_executor/models/qwen3_moe.py:84-87).

  4. 4
    How do you select the deterministic benchmark routing, and why not use it for serving?
    medium
    Show answer

    Set VLLM_MOE_ROUTING_SIMULATION_STRATEGY=afd_balanced (afd_plugin/model_executor/routing_simulator.py:5-8). It replaces real routing with a synthetic cycle, so it changes model outputs (afd_plugin/model_executor/routing_simulator.py:10-11).

  5. 5
    On an NPU, what does BATCH_SIZE_FACTOR control, and from what base?
    hard
    Show answer

    It multiplies the CAM receive capacity, base 262144 tokens, with native float rounding; default 1 (afd_plugin/validation.py:45-54). It has no effect on GPU.

Related pages

  • Dual-batch overlap (DBO): two stages per stepDBO splits one step into exactly two stages. While one stage waits on the FFN side, the other computes attention, so the two roles stay busy. AFD adds a yield op and scoped patches for DP1.
  • CUDA graphs in AFD: FULL_DECODE_ONLY on both rolesAFD supports one CUDA graph mode, FULL_DECODE_ONLY. The attention side wraps native capture and replay to publish control; the FFN side keeps its own graph per token shape.
  • Environment variables referenceEvery environment variable that afd-plugin reads or sets, generated from the source, with defaults and read sites. A hand section lists the vLLM variables that AFD depends on.
  • Recipes referenceEvery recipe script under recipe/, generated from the source, with hardware, connector, model, topology, role, DP/TP, mode, DBO thresholds and ports. Hand notes cover the parts the parser cannot read.
  • The MoE handoff: where the gate runsThe compute_gate_on_attention flag decides whether the MoE gate runs on the attention side or the FFN side. The choice changes which classes build, what crosses the connector, and which layers the FFN runs.
