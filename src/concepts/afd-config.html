This page shows its schema, the compatibility aliases, how values are normalized and coerced, the validation rules, and the rule that AFD is active only when the key is present. --- AFD reads one key, {{term additional-config | additional_config["afd"]}}. The plugin renames aliases, coerces types, builds {{term afd-config | AFDConfig}}, then validates it.

The idea

vLLM has one open config field for out-of-tree code, additional_config ({{cite vllm:vllm/config/vllm.py:434}}). afd-plugin reads one key inside it, "afd" ({{cite afd_plugin/config.py:20}}). The value is a mapping of AFD settings: the role, the connector, the topology sizes and the rendezvous host and port.

The plugin does not use the raw mapping directly. It renames old afd_* aliases to short names, coerces the types, builds a frozen dataclass, and validates the result. One flag decides whether AFD runs at all: AFD is active only when the "afd" key is present.

An everyday comparison. Think of a form with a few fields and some old field names kept for compatibility. A clerk renames the old names, checks each value, and files one clean record. The comparison stops here: a missing form here does not mean an error, it means AFD stays off.

In the code

Step 2: Aliases

Five old afd_* names stay valid as read-only aliases. Normalization renames each to its short name ({{cite afd_plugin/config.py:32-38}}).

So the recipe may write "afd_role" or "role"; both reach the role field ({{cite afd_plugin/config.py:128}}).

Step 3: Normalization and coercion

_normalize_mapping renames the aliases, splits out connector_extra_config, rejects an unknown field, and coerces the typed fields ({{cite afd_plugin/config.py:120-176}}). The integer fields use coerce_extra_int, which rejects a bool or a float instead of truncating it ({{cite afd_plugin/config_utils.py:35-45}}).

Step 4: The validation rules

validate_afd_config checks the built config without importing vLLM or CUDA ({{cite afd_plugin/config.py:311-350}}). The rules:

  • the role is "attention" or "ffn" ({{cite afd_plugin/config.py:318-321}});
  • the connector name is one of the three supported names ({{cite afd_plugin/config.py:326-330}});
  • async_dp needs the async connector ({{cite afd_plugin/config.py:331-334}});
  • the host is non-empty and the port is in 1..65535 ({{cite afd_plugin/config.py:339-342}});
  • both rank counts are positive ({{cite afd_plugin/config.py:343-350}}).

Step 5: AFD is active only when the key is present

is_afd_active parses the optional config and returns true only when a present "afd" key passes validation ({{cite afd_plugin/config.py:289-292}}). When the key is absent, parse_optional_afd_config returns None and AFD stays off ({{cite afd_plugin/config.py:244-259}}).

Step 6: Per-connector options

Options that belong to one connector go under connector_extra_config, not next to the AFD fields. Normalization keeps this sub-mapping aside ({{cite afd_plugin/config.py:129-133}}). Each connector parses its own keys later, through parse_extra_config ({{cite afd_plugin/connectors/base.py:64-72}}). The {{link reference/afd-config}} page lists each connector's keys.

Deep dive

The 2a2f recipe sets num_attention_ranks to 2 in the attention server's config ({{cite recipe/gpu/P2pNcclAFDConnector/deepseek_v2_lite/prefill_decode_colocation/2a2f_eager_dbo_dp1tp2.sh:17}}). Follow that value:

  1. Read. The plugin reads additional_config["afd"], which holds the mapping ({{cite afd_plugin/config.py:227-234}}).
  2. Normalize. num_attention_ranks is not an alias and is a valid field, so it is kept ({{cite afd_plugin/config.py:127-145}}).
  3. Coerce. It is in the integer list, so coerce_extra_int(2) returns 2; a float or a bool would raise ({{cite afd_plugin/config.py:153-162}}, {{cite afd_plugin/config_utils.py:35-45}}).
  4. Build. The value becomes AFDConfig.num_attention_ranks ({{cite afd_plugin/config.py:190}}).
  5. Validate. The rank count must be positive ({{cite afd_plugin/config.py:343-346}}).
  6. Use. At device init, the runtime check needs the attention rank count to equal data-parallel size times tensor-parallel size. This recipe runs DP1 TP2, so the value must be 2 ({{cite afd_plugin/validation.py:107-117}}).

So a field default of 1 ({{cite afd_plugin/config.py:62}}) is only the start; the final value comes from the recipe, and a runtime rule ties it to the parallel sizes.

{{term async-dp}} turns on AFD's async data-parallel patches. It is read by is_afd_async_dp, which returns true only when the flag is set and the connector is the async CAM connector ({{cite afd_plugin/config.py:295-308}}). That connector is NPU-only, so the flag has no effect on GPU.

  • Validation. async_dp without the async connector raises ({{cite afd_plugin/config.py:331-334}}).
  • GPU runtime. The GPU runner check needs the synchronous P2pNcclAFDConnector ({{cite afd_plugin/validation.py:94-97}}). So the async connector, and therefore async_dp, cannot be active on GPU.
  • Where it takes effect. On NPU, is_afd_async_dp selects the async-DP patches from the flag and the connector ({{cite afd_plugin/config.py:303-308}}). Those patches are NPU code; see {{link concepts/npu-overview}}.

What can go wrong

  • Unknown field. A key that is not a field and not an alias raises ValueError; the message points to connector_extra_config ({{cite afd_plugin/config.py:134-139}}).
  • Alias and canonical together. Passing both afd_role and role raises a duplicate-field error ({{cite afd_plugin/config.py:140-144}}).
  • Wrong type for an integer. A float or a bool for port or a rank count raises TypeError, not a silent truncation ({{cite afd_plugin/config_utils.py:38-39}}).
  • async_dp on GPU. It fails validation unless the connector is the async CAM connector, which GPU does not use ({{cite afd_plugin/config.py:331-334}}).

Why it matters. Both roles parse the same schema. A typo or a wrong type stops start-up with a clear error, instead of a silent mismatch between the two servers.

What makes AFD active?

The presence of the "afd" key in additional_config. Without it, parse returns None and AFD stays off ({{cite afd_plugin/config.py:244-259}}, {{cite afd_plugin/config.py:289-292}}).

 Where do connector-specific options go?

Under connector_extra_config, not next to the AFD fields. Each connector parses its own keys ({{cite afd_plugin/config.py:71-73}}, {{cite afd_plugin/connectors/base.py:64-72}}).

 A recipe passes "port": 6269.0. What happens?

It raises TypeError. coerce_extra_int rejects a float instead of truncating it ({{cite afd_plugin/config_utils.py:38-39}}).

 On what platform does async_dp have an effect?

NPU only. It needs the async CAM connector ({{cite afd_plugin/config.py:295-308}}), which GPU does not use ({{cite afd_plugin/validation.py:94-97}}).

 The field default for num_attention_ranks is 1, but the 2a2f recipe runs with 2. What final rule ties the value to the deployment?

At device init, the attention rank count must equal data-parallel size times tensor-parallel size. With DP1 TP2 the value must be 2 ({{cite afd_plugin/validation.py:107-117}}). The default is only the start; the recipe sets the real value ({{cite recipe/gpu/P2pNcclAFDConnector/deepseek_v2_lite/prefill_decode_colocation/2a2f_eager_dbo_dp1tp2.sh:17}}).
