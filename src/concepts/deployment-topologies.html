This page gives the process count, GPUs, ranks, flags, start order and ports of each. --- AFD runs as two or more vllm serve processes. A topology says how many {{term attention-role | attention}} and {{term ffn-role | FFN}} ranks there are, and where they run.

The idea

AFD splits one model into an attention role and an FFN role. Each role is a separate {{term attention-server | server}} process. A topology name xAyF gives the counts: x attention ranks and y FFN ranks ({{term xayf | xAyF}}). The GPU recipes ship five shapes of this split.

Two rules fix the rank counts. For each role, the rank count must equal DP × TP: the attention ranks equal the attention server's data-parallel size times its tensor-parallel size, and the same for FFN ({{cite afd_plugin/validation.py:107-117}}). The attention ranks must also be at least the FFN ranks, A >= F ({{cite afd_plugin/distributed/topology.py:52-58}}).

An everyday comparison. Think of a kitchen with a front counter and a back kitchen. The counter takes orders (attention); the kitchen cooks (FFN). You can add counters or cooks, but you need at least as many counters as cooks, and each team's size is set when you open. The comparison stops at the wire: the two teams talk only through the {{term connector}}.

In the code

Step 1: The rank rule (A = DP x TP, F = DP x TP)

The validator reads the role's rank count and compares it with DP × TP of that server. A mismatch raises before the run starts ({{cite afd_plugin/validation.py:107-117}}).

So a 2A2F topology has two ways to reach two attention ranks: DP1 TP2 or DP2 TP1. Both give 2 = DP × TP. The {{link concepts/topology}} page covers how a role rank maps to a world rank.

Step 2: Colocation 2A2F (two servers, four GPUs)

The simplest recipe runs one attention server on GPUs 0 and 1, and one FFN server on GPUs 2 and 3. Each server sets num_attention_ranks: 2 and num_ffn_ranks: 2, so the topology is 2A2F ({{cite recipe/gpu/P2pNcclAFDConnector/deepseek_v2_lite/prefill_decode_colocation/2a2f_graph_dbo_dp1tp2.sh:7-32}}).

The DP/TP split is a choice. The dp1tp2 variant uses DP1 TP2 ({{cite recipe/gpu/P2pNcclAFDConnector/deepseek_v2_lite/prefill_decode_colocation/2a2f_graph_dbo_dp1tp2.sh:8-9}}); the dp2tp1 variant uses DP2 TP1 ({{cite recipe/gpu/P2pNcclAFDConnector/deepseek_v2_lite/prefill_decode_colocation/2a2f_eager_dbo_dp2tp1.sh:8-9}}). Both give two ranks per role.

Step 3: Colocation 4A4F (double both roles)

The 4A4F recipe doubles both sides: four attention ranks on GPUs 0-3, four FFN ranks on GPUs 4-7, each server DP2 TP2 ({{cite recipe/gpu/P2pNcclAFDConnector/deepseek_v2_lite/prefill_decode_colocation/4a4f_graph_dbo_dp2tp2.sh:7-18}}).

Step 4: Disaggregation 2P1A1F (prefillers and a proxy)

The disaggregation recipe adds a prefill stage. It runs five processes: two prefillers, one attention decode server, one FFN decode server, and a proxy ({{cite recipe/gpu/P2pNcclAFDConnector/deepseek_v2_lite/README.md:40-50}}). The attention and FFN servers each use 1A1F ({{cite recipe/gpu/P2pNcclAFDConnector/deepseek_v2_lite/prefill_decode_disaggregation/2p1a1f_eager_dbo.sh:56-98}}).

The proxy is tools/proxy_server.py, copied from vLLM-Ascend ({{cite tools/proxy_server.py:1}}). It splits prefill and decode with a NIXL KV transfer, not attention and FFN. The attention/FFN split still happens on the decode pair, over AFD port 6269 ({{cite recipe/gpu/P2pNcclAFDConnector/deepseek_v2_lite/prefill_decode_disaggregation/2p1a1f_eager_dbo.sh:81-85}}).

Step 5: Multipod on Kubernetes

The {{term multipod}} recipes put one role per pod. Each vllm serve is wrapped in an if [ "$POD" == ... ] block, so with POD unset neither block runs ({{cite recipe/gpu/P2pNcclAFDConnector/deepseek_v2_lite/prefill_decode_colocation/multipod_2a_2f_graph_dbo_dp1tp2.sh:15-16}}). These scripts are for the deploy-afd-k8s skill, not for a local run ({{cite recipe/gpu/P2pNcclAFDConnector/deepseek_v2_lite/README.md:62-69}}).

The Qwen3.5 122B FP8 recipe is a three-pod 4A2F split: two attention pods and one FFN pod. The second attention pod sets ATTENTION_HEADLESS=1 and ATTENTION_DP_START_RANK=2, so the four attention ranks (DP4, DP2 local on each pod) come from two pods, and the FFN pod runs DP2 ({{cite recipe/gpu/P2pNcclAFDConnector/qwen3_5_122b_a10b_fp8/prefill_decode_colocation/multipod_2a_2a_2f_graph.sh:3-8}}, {{cite recipe/gpu/P2pNcclAFDConnector/qwen3_5_122b_a10b_fp8/prefill_decode_colocation/multipod_2a_2a_2f_graph.sh:46-55}}).

The Qwen3.5 topology is the one case where A > F (4 > 2). The attention ranks spread over the FFN ranks in blocks that differ in size by at most one ({{cite afd_plugin/distributed/topology.py:118-146}}). See {{link concepts/topology}}.

Each DeepSeek-V2-Lite colocation topology ships an eager and a graph variant. They differ in two flags.

  • Eager. The *_eager_* scripts pass --enforce-eager ({{cite recipe/gpu/P2pNcclAFDConnector/deepseek_v2_lite/prefill_decode_colocation/2a2f_eager_dbo_dp1tp2.sh:26}}).
  • Graph. The *_graph_* scripts replace it with --max-cudagraph-capture-size 64 and --compilation-config '{"cudagraph_mode": "FULL_DECODE_ONLY", "cudagraph_capture_sizes":[64]}' ({{cite recipe/gpu/P2pNcclAFDConnector/deepseek_v2_lite/prefill_decode_colocation/2a2f_graph_dbo_dp1tp2.sh:26-29}}).

On GPU, only {{term full-decode-only | FULL_DECODE_ONLY}} is allowed ({{cite afd_plugin/v1/worker/cuda_graph.py:20-21}}). The {{link concepts/cuda-graphs}} page covers capture and replay, and {{link concepts/tuning}} covers the capture size.

A recipe backgrounds its serve processes, writes attn.log and ffn.log, then waits ({{cite recipe/gpu/P2pNcclAFDConnector/deepseek_v2_lite/prefill_decode_colocation/2a2f_graph_dbo_dp1tp2.sh:29-61}}).

  1. Both roles start together. They meet at the AFD {{term rendezvous}} host:port, default 127.0.0.1:1239; the recipes set 6269 ({{cite recipe/gpu/P2pNcclAFDConnector/deepseek_v2_lite/prefill_decode_colocation/2a2f_graph_dbo_dp1tp2.sh:15-16}}).
  2. Wait for Application startup complete in each log before you send traffic ({{cite recipe/gpu/P2pNcclAFDConnector/README.md:39-43}}).
  3. Send requests only to the attention HTTP port (18305 for colocation, 18303 for the disaggregation decode server) ({{cite README.md:258-260}}).

The two ports differ in meaning. The AFD port (6269) is where the two roles set up the connector groups. The HTTP port (18305) is where clients send requests.

What can go wrong

This page shows the GPU recipes. The NPU recipes use different topologies and scales (for example 48A16F), covered on {{link concepts/npu-overview}}.
  • Rank count does not match DP x TP. The validator raises when num_attention_ranks != DP × TP for the attention server, or the same for FFN ({{cite afd_plugin/validation.py:107-117}}).
  • A < F. The GPU connector requires num_attention_ranks >= num_ffn_ranks and raises otherwise ({{cite afd_plugin/distributed/topology.py:52-58}}).
  • A multipod script run locally. With POD unset, neither serve block runs, so nothing starts ({{cite recipe/gpu/P2pNcclAFDConnector/deepseek_v2_lite/prefill_decode_colocation/multipod_2a_2f_graph_dbo_dp1tp2.sh:15-16}}).
  • A host or port mismatch between the roles. Both roles must use the same AFD host:port, or the group setup hangs until the timeout ({{cite afd_plugin/connectors/gpu/p2p.py:271}}).

Why it matters. The topology fixes the process count, the GPU count and the rank mapping. A wrong rank count or a wrong host stops the run before the first token.

A 2A2F topology can use which two DP/TP splits per role?

DP1 TP2 or DP2 TP1. Both give two ranks, because the rank count must equal DP × TP ({{cite afd_plugin/validation.py:107-117}}).

 How many vllm serve processes does the 2P1A1F recipe start, and what are they?

Five: two prefillers, one attention decode server, one FFN decode server, and a proxy ({{cite recipe/gpu/P2pNcclAFDConnector/deepseek_v2_lite/README.md:40-50}}).

 What does the proxy in 2P1A1F do, and why is it not part of the attention/FFN split?

It load-balances prefill and decode with a NIXL KV transfer ({{cite tools/proxy_server.py:1}}). The attention/FFN split happens on the decode pair over AFD port 6269, a different path ({{cite recipe/gpu/P2pNcclAFDConnector/deepseek_v2_lite/prefill_decode_disaggregation/2p1a1f_eager_dbo.sh:81-85}}).

 In the Qwen3.5 multipod recipe, how do two attention pods make four attention ranks?

Each pod runs DP2 local, and the second pod sets ATTENTION_DP_START_RANK=2, so together they form DP4 (four ranks); the FFN pod runs DP2 ({{cite recipe/gpu/P2pNcclAFDConnector/qwen3_5_122b_a10b_fp8/prefill_decode_colocation/multipod_2a_2a_2f_graph.sh:3-8}}, {{cite recipe/gpu/P2pNcclAFDConnector/qwen3_5_122b_a10b_fp8/prefill_decode_colocation/multipod_2a_2a_2f_graph.sh:46-55}}).

 The graph variants replace one flag. Which flag, with what, and which graph mode is allowed on GPU?

They replace --enforce-eager with --max-cudagraph-capture-size 64 and a --compilation-config that sets cudagraph_mode to FULL_DECODE_ONLY ({{cite recipe/gpu/P2pNcclAFDConnector/deepseek_v2_lite/prefill_decode_colocation/2a2f_graph_dbo_dp1tp2.sh:26-29}}). GPU AFD allows only FULL_DECODE_ONLY ({{cite afd_plugin/v1/worker/cuda_graph.py:20-21}}).
