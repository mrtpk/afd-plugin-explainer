--- summary: A study site for afd-plugin, the vLLM external plugin for Attention-FFN Disaggregation (AFD). It explains the code at two pinned commits. ---

{{project name}} is a {{term plugin | vLLM external plugin}} for {{term afd}}. The attention part and the feed-forward (FFN/MoE) part of a model run in two separate server processes, and a {{term connector}} moves hidden states between them. The plugin adds its own worker classes, model runners, model wrappers, connectors, config validation and compatibility {{term patch | patches}}, and it changes no vLLM source file ({{cite README.md:9-13}}, {{cite README.md:21-24}}). This site explains the plugin code at commit {{project short_sha}}, and the vLLM code it builds on at commit {{project vllm_short_sha}}. You need to know Python and the basics of LLM serving.

At a glance

What it isA vLLM external plugin for Attention-FFN Disaggregation (AFD) ({{cite README.md:9-13}}).
Runs onNVIDIA CUDA GPU and Ascend NPU ({{cite README.md:11-13}}). This site explains the GPU paths in full; one page, {{link concepts/npu-overview}}, covers the NPU.
TargetsvLLM v0.30.0 at commit {{project vllm_short_sha}} ({{cite README.md:21}}, {{cite pyproject.toml:37}}). Other vLLM versions are not supported on GPU ({{cite README.md:69-70}}).
ModelsDeepSeek V2 / V3 / V3.2 / V4, GLM-MoE-DSA, Qwen3-MoE, and one Qwen3.5-MoE architecture, Qwen3_5MoeForConditionalGeneration (the README lists this one under "Qwen3.5 / Qwen3.6 MoE"). The code registers eight architectures, each under an AFD-prefixed name ({{cite afd_plugin/__init__.py:96-131}}, {{cite README.md:47-51}}).
ConnectorsThree: P2pNcclAFDConnector (CUDA), CAMP2pAFDConnector and CAMAsyncAFDConnector (both NPU) ({{cite afd_plugin/connectors/factory.py:88-102}}).
Code sizeAbout 20,195 lines of Python in afd_plugin/, across 78 files. The C/C++ kernels in csrc/ are out of scope. See {{link code/index}} for the breakdown and the method.
How to runStart two vllm serve processes, one for each role, and give each one --additional-config '{"afd":{ ... }}'. Send requests only to the attention API server ({{cite README.md:218-240}}, {{cite README.md:258-260}}).

What is not in this release

This site has limits of scope, and the plugin itself states limits.

Out of the site's scope.

  • The C/C++ kernel sources in csrc/. The site explains only how the Python code selects, builds, loads and calls them.
  • The Ascend NPU code, except the one overview page {{link concepts/npu-overview}}. Other pages name the NPU variant in one line only.
  • The tests. They are a source of facts, not a page topic.

What the repository calls experimental or limited.

  • The project is experimental and needs more large-scale testing ({{cite README.md:17-19}}).
  • The GPU target is exactly vLLM 0.30.0; other versions are not supported on GPU ({{cite README.md:69-70}}).
  • GPU CUDA graphs are limited to FULL_DECODE_ONLY ({{cite README.md:86}}).
  • Native {{term dbo | DBO}} is limited to exactly two {{term ubatch | ubatches}} ({{cite README.md:87}}).
  • Qwen3-MoE rejects attention-side gate placement, sequence-parallel MoE, EPLB, pipeline parallelism, speculative decoding, LoRA and NPU ({{cite README.md:91-92}}).
  • The GPU and NPU end-to-end tests are opt-in and need real hardware and model weights ({{cite README.md:85}}).

The code version this site explains

So every line number on this site is stable only at these two commits.
