How the config is passed

You give AFD config to vLLM under one key. Each vllm serve process gets --additional-config '{"afd": { ... }}'. vLLM stores the outer mapping on its {{term additional-config}} field ({{cite vllm:vllm/config/vllm.py:434}}). The plugin reads the inner "afd" mapping and builds an {{term afd-config | AFDConfig}} dataclass ({{cite afd_plugin/config.py:42}}).

The two tables in the next section are generated from the source. The validation, read-site and example tables that follow are hand-written, each row with a citation.

Validation rules

The plugin coerces each value to its type, then validates it. Coercion happens in _normalize_mapping ({{cite afd_plugin/config.py:120-176}}); validation happens in validate_afd_config ({{cite afd_plugin/config.py:311-350}}). An invalid value raises before the run starts.

Unknown afd key raises ValueErrorany key not a field or alias {{cite afd_plugin/config.py:134-139}}

role must be "attention" or "ffn"role {{cite afd_plugin/config.py:318-321}}

For P2pNcclAFDConnector: num_attention_ranks >= num_ffn_ranks GPU P2P only{{cite afd_plugin/distributed/topology.py:52-58}}
Booleans accept true/false, 1/0, yes/no, on/off async_dp, compute_gate_on_attention {{cite afd_plugin/config_utils.py:8-24}}
Integers reject bool and float inputs port, rank counts{{cite afd_plugin/config_utils.py:35-45}}

Each connector parses connector_extra_config in its own parse_extra_config hook, and rejects unknown keys there ({{cite afd_plugin/connectors/base.py:64-72}}). The GPU connector accepts no keys at all ({{cite afd_plugin/connectors/gpu/p2p.py:146-158}}).

Where the final value is set

Lesson from the fact checks: a default is not final until the code sets it. Trace each value through four steps. A missing key takes the dataclass default; a present key is coerced, stored, then validated.

  1. Recipe or CLI. The --additional-config JSON gives the raw mapping. vLLM stores it on additional_config ({{cite vllm:vllm/config/vllm.py:434}}).
  2. Normalize. _normalize_mapping rewrites aliases, splits out connector_extra_config, and coerces port, the rank counts, the timeout and the booleans ({{cite afd_plugin/config.py:147-174}}).
  3. Construct. AFDConfig(**normalized) fills any absent key with the dataclass default ({{cite afd_plugin/config.py:189-190}}). So the defaults in the table apply only to keys the recipe omits.
  4. Validate. validate_afd_config raises on a bad value ({{cite afd_plugin/config.py:311-350}}). The worker re-parses and re-validates through assert_compatible_afd_stack ({{cite afd_plugin/validation.py:328}}).

Worked example: the recipe's afd block

This block is the attention server from the simplest GPU recipe, 2a2f_eager_dbo_dp1tp2.sh ({{cite recipe/gpu/P2pNcclAFDConnector/deepseek_v2_lite/prefill_decode_colocation/2a2f_eager_dbo_dp1tp2.sh:11-20}}). The FFN server uses the same block with "role": "ffn". The tour {{link tours/life-of-a-request}} follows a request through this recipe.

{
  "afd": {
    "role": "attention",
    "connector": "P2pNcclAFDConnector",
    "host": "127.0.0.1",
    "port": 6269,
    "num_attention_ranks": 2,
    "num_ffn_ranks": 2
  }
}
KeyValueEffect for this recipe
role"attention" This server runs the attention worker and the API server. The FFN server sets "ffn".
connector"P2pNcclAFDConnector" The GPU connector. It takes no connector_extra_config.
host, port"127.0.0.1", 6269 Both servers meet at this address. The value overrides the default port 1239.
num_attention_ranks2 Two attention ranks (A0, A1). The server runs --tensor-parallel-size 2.
num_ffn_ranks2 Two FFN ranks (F0, F1). A0 maps to F0 and A1 maps to F1 ({{cite afd_plugin/distributed/topology.py:135-136}}).

The recipe omits five keys, so they take their defaults: async_dp=false, compute_gate_on_attention=false, afd_process_group_timeout_s=120, an empty connector_extra_config, and the coerced port and rank integers. The A >= F rule holds because both counts are 2 ({{cite afd_plugin/distributed/topology.py:52-58}}).
