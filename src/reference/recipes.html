How to read this table

Each recipe script runs one or more vllm serve processes. The table has one row per process that carries an "afd" block, so one row per {{term attention-role | attention}} or {{term ffn-role | FFN}} process. The topology name links to {{link concepts/deployment-topologies}}, which explains each layout. The generator parses the shell text only; it never runs a script.

Run python3 tools/gen_recipes.py to refresh the table at the pinned commit.

Some scripts set a value from an environment variable, for example num_attention_ranks from $ATTENTION_RANKS. The table shows the variable name, because the real value is set at launch. The multipod scripts show $AFD_CONNECTOR_PORT for the same reason.

What the parser cannot read

The generator reads the AFD serve processes. These parts of the recipes are not in the table, so they are listed here by hand, each with a citation.

  • The multipod POD gate. The multipod scripts wrap each vllm serve in an if [ "$POD" == ... ] block. With POD unset, neither block runs ({{cite recipe/gpu/P2pNcclAFDConnector/deepseek_v2_lite/prefill_decode_colocation/multipod_2a_2f_graph_dbo_dp1tp2.sh:15-16}}, {{cite recipe/gpu/P2pNcclAFDConnector/deepseek_v2_lite/prefill_decode_colocation/multipod_2a_2f_graph_dbo_dp1tp2.sh:44-45}}). These scripts are for the deploy-afd-k8s skill, one pod per role, not for a local run ({{cite recipe/gpu/P2pNcclAFDConnector/deepseek_v2_lite/README.md:62-69}}).
  • The Qwen3.5 multipod attention split. The Qwen recipe runs two attention pods (POD=ATTENTION_0 and POD=ATTENTION_1 with ATTENTION_DP_START_RANK=2) and one FFN pod, so num_attention_ranks=4 is split across two pods (DP4, DP2 local each), and num_ffn_ranks=2 ({{cite recipe/gpu/P2pNcclAFDConnector/qwen3_5_122b_a10b_fp8/prefill_decode_colocation/multipod_2a_2a_2f_graph.sh:3-8}}, {{cite recipe/gpu/P2pNcclAFDConnector/qwen3_5_122b_a10b_fp8/prefill_decode_colocation/multipod_2a_2a_2f_graph.sh:33-34}}).
  • The 2P1A1F prefillers and proxy. The disaggregation recipe also starts two prefill servers and a proxy. They carry no "afd" block, so they are not in the table. The prefillers use a NIXL KV connector ({{cite recipe/gpu/P2pNcclAFDConnector/deepseek_v2_lite/prefill_decode_disaggregation/2p1a1f_eager_dbo.sh:22-50}}); the proxy is tools/proxy_server.py ({{cite recipe/gpu/P2pNcclAFDConnector/deepseek_v2_lite/prefill_decode_disaggregation/2p1a1f_eager_dbo.sh:110-125}}). See {{link concepts/deployment-topologies}}.
  • The NPU baseline_ep64.sh. The CAMP2p folder also holds a non-AFD EP64 baseline for comparison, with no "afd" block ({{cite recipe/npu/CAMP2pAFDConnector/deepseek_v3_2/baseline_ep64.sh:1}}).
  • NPU topology names. The NPU CAMP2p scripts set num_attention_ranks=$ATTENTION_RANKS, so the table cannot print an xAyF label. The README documents the real scales: EP64 baseline, 48A16F and 64A16F ({{cite recipe/npu/CAMP2pAFDConnector/deepseek_v3_2/README.md:28-33}}).

DBO thresholds in the recipes

Every DeepSeek-V2-Lite recipe turns on {{term dbo | DBO}} with --dbo-decode-token-threshold 2 --dbo-prefill-token-threshold 12. The README calls these example values and says to tune them ({{cite recipe/gpu/P2pNcclAFDConnector/deepseek_v2_lite/README.md:140-143}}). The vLLM defaults are higher, 32 and 512 ({{cite vllm:vllm/config/parallel.py:227}}, {{cite vllm:vllm/config/parallel.py:232}}). See {{link concepts/tuning}}.

Running a recipe

Run a colocation script from the repository root. It backgrounds the attention and FFN servers and writes attn.log and ffn.log ({{cite recipe/gpu/P2pNcclAFDConnector/README.md:30-43}}). Wait for Application startup complete in each log, then send traffic to the attention HTTP port. The tour {{link tours/run-a-recipe}} walks one script line by line.

export MODEL_PATH=/path/model_weights/DeepSeek-V2-Lite
export VLLM_USE_V2_MODEL_RUNNER=1
bash recipe/gpu/P2pNcclAFDConnector/deepseek_v2_lite/prefill_decode_colocation/2a2f_graph_dbo_dp1tp2.sh
