Hand-checked, one row per replaced function. --- This table lists every {{term patch}} in afd_plugin/compat/patches/, its vLLM target at the pinned commit, its install mechanism, when it is active, and what it changes.

How to read this table

Each row is one replaced function. The vLLM target is the function the patch stands in for, at the pinned vLLM commit ({{project vllm_short_sha}}). The install column says where and how AFD installs the patch and what gates it. The active when column says which configs the patch actually changes; the others see native behavior. Every GPU patch is behind the {{term version-gate | version gate}} is_target_vllm_compatible ({{cite afd_plugin/compat/vllm.py:53-68}}). The concept page is {{link concepts/compat-patches}}.

What is not patched

AFD does not patch the API server, the scheduler, the sampler or the attention and KV kernels. The attention runner wraps native methods instead of replacing them ({{cite afd_plugin/v1/worker/attention_model_runner_v2.py:569-595}}), and sampling stays native ({{cite vllm:vllm/v1/worker/gpu/model_runner.py:2048-2050}}).
