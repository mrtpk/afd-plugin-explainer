The idea

A recipe is a shell script that starts the two {{term attention-server | servers}} of an AFD run. This tour reads 2a2f_graph_dbo_dp1tp2.sh, the 2A2F graph recipe for DeepSeek-V2-Lite ({{cite recipe/gpu/P2pNcclAFDConnector/deepseek_v2_lite/prefill_decode_colocation/2a2f_graph_dbo_dp1tp2.sh:1-61}}). It starts one {{term attention-role | attention}} server on two GPUs and one {{term ffn-role | FFN}} server on two GPUs, with CUDA graphs and {{term dbo | DBO}} on.

Both servers use the same --additional-config block; only role and the GPUs differ. The {{link reference/recipes}} page lists every recipe; the {{link tours/life-of-a-request}} tour follows a request through this same recipe.

The picture

Read panel 1 as the two serve commands, side by side. Read panel 2 as the order: background both, wait for startup, then send requests to the attention port.

The script exports one environment variable before it starts a server ({{cite recipe/gpu/P2pNcclAFDConnector/deepseek_v2_lite/prefill_decode_colocation/2a2f_graph_dbo_dp1tp2.sh:5}}).

AFD runs on {{term model-runner-v2 | Model Runner V2}}. Setting VLLM_USE_V2_MODEL_RUNNER=1 turns the V2 runner on explicitly. vLLM also picks V2 by default when the variable is unset ({{cite vllm:vllm/config/vllm.py:692-694}}); the recipe sets it so the choice is clear. The validator raises only when V2 resolves to off ({{cite afd_plugin/validation.py:90-91}}).

The attention server runs on GPUs 0 and 1. The parallel flags set the per-role rank count ({{cite recipe/gpu/P2pNcclAFDConnector/deepseek_v2_lite/prefill_decode_colocation/2a2f_graph_dbo_dp1tp2.sh:7-10}}).

  • CUDA_VISIBLE_DEVICES=0,1 picks the two GPUs for this role.
  • --data-parallel-size 1 --tensor-parallel-size 2 gives two attention ranks, because the rank count must equal DP × TP ({{cite afd_plugin/validation.py:107-117}}).
  • --enable-expert-parallel turns on static expert parallelism, which AFD requires ({{cite afd_plugin/validation.py:118-125}}).

See {{link concepts/deployment-topologies}} for the rank rule.

The --additional-config JSON carries the AFD settings under the "afd" key ({{cite recipe/gpu/P2pNcclAFDConnector/deepseek_v2_lite/prefill_decode_colocation/2a2f_graph_dbo_dp1tp2.sh:11-20}}).

The plugin reads this inner mapping and builds an {{term afd-config | AFDConfig}} ({{cite afd_plugin/config.py:42}}). The role is attention here; the connector is the GPU {{term connector | P2P connector}}; host and port set the {{term rendezvous}} where the two roles meet; num_attention_ranks and num_ffn_ranks are both 2. See {{link reference/afd-config}}.

The next flags set the batch limits, DBO and the CUDA graph ({{cite recipe/gpu/P2pNcclAFDConnector/deepseek_v2_lite/prefill_decode_colocation/2a2f_graph_dbo_dp1tp2.sh:21-29}}).

  • --enable-dbo with --dbo-decode-token-threshold 2 and --dbo-prefill-token-threshold 12 turns on {{term dbo | DBO}} with low example thresholds. AFD needs exactly two microbatches when DBO is on ({{cite afd_plugin/validation.py:126-131}}). See {{link concepts/dbo}}.
  • --max-cudagraph-capture-size 64 and the --compilation-config with cudagraph_mode: FULL_DECODE_ONLY turn on CUDA graphs. GPU AFD allows only FULL_DECODE_ONLY ({{cite afd_plugin/v1/worker/cuda_graph.py:20-21}}). See {{link concepts/cuda-graphs}}.

The attention server binds an HTTP port and runs in the background ({{cite recipe/gpu/P2pNcclAFDConnector/deepseek_v2_lite/prefill_decode_colocation/2a2f_graph_dbo_dp1tp2.sh:30-32}}).

Clients connect to this HTTP port, 18305. It is a different port from the AFD 6269: the HTTP port carries requests, the AFD port carries the connector setup. The command ends with &, so it runs in the background.

The FFN server is the same command with two changes: GPUs 2 and 3, and role: ffn ({{cite recipe/gpu/P2pNcclAFDConnector/deepseek_v2_lite/prefill_decode_colocation/2a2f_graph_dbo_dp1tp2.sh:34-59}}).

The FFN server reads the same host, port and rank counts, so the two roles meet at the same rendezvous. It runs no KV cache and no real scheduler, only a no-op stand-in; the connector drives it ({{cite afd_plugin/compat/patches/engine_core.py:599-623}}). Send no client traffic here. See {{link concepts/roles}} and {{link concepts/ffn-runtime}}.

The script backgrounds both servers and ends with wait ({{cite recipe/gpu/P2pNcclAFDConnector/deepseek_v2_lite/prefill_decode_colocation/2a2f_graph_dbo_dp1tp2.sh:53-61}}).

Both roles start together and meet at the AFD rendezvous. Wait for Application startup complete in each log before you send traffic ({{cite recipe/gpu/P2pNcclAFDConnector/README.md:39-43}}).

Set the model path and the V2 runner, then run the script ({{cite recipe/gpu/P2pNcclAFDConnector/deepseek_v2_lite/README.md:88-92}}).

export MODEL_PATH=/path/model_weights/DeepSeek-V2-Lite
export VLLM_USE_V2_MODEL_RUNNER=1
bash recipe/gpu/P2pNcclAFDConnector/deepseek_v2_lite/prefill_decode_colocation/2a2f_graph_dbo_dp1tp2.sh

The script writes attn.log and ffn.log in the current directory.

Send requests only to the attention HTTP server ({{cite README.md:258-260}}). The FFN server has no request path; a request there fails fast ({{cite afd_plugin/v1/worker/ffn_worker.py:122-131}}).

curl http://127.0.0.1:18305/v1/completions \
  -H 'Content-Type: application/json' \
  -d '{"model": "'"$MODEL_PATH"'", "prompt": "Hello", "max_tokens": 16}'

To benchmark, drive load against the same port with the repository's wrapper around vllm bench serve ({{cite tools/benchmarks/request_generator.sh:44-57}}). The README shows the benchmark command for this model ({{cite recipe/gpu/P2pNcclAFDConnector/deepseek_v2_lite/README.md:104-120}}). See {{link concepts/tuning}}.

What can go wrong

  • A request sent to the FFN server. The FFN worker is connector-driven; a scheduler-driven execute_model raises at once ({{cite afd_plugin/v1/worker/ffn_worker.py:122-131}}).
  • Different host or port on the two roles. Both must use the same AFD host:port, or the group setup hangs until the timeout ({{cite afd_plugin/connectors/gpu/p2p.py:271}}).
  • Traffic sent before startup. Wait for Application startup complete in both logs first ({{cite recipe/gpu/P2pNcclAFDConnector/README.md:39-43}}).
  • The rank count does not match DP x TP. The validator raises before the run starts ({{cite afd_plugin/validation.py:107-117}}).

Why it matters. The recipe is the full launch contract. One wrong flag, port, or target stops the run or hangs the rendezvous.

Which port do clients connect to, and which port is the AFD rendezvous?

Clients connect to the HTTP port 18305; the roles meet at the AFD port 6269 ({{cite recipe/gpu/P2pNcclAFDConnector/deepseek_v2_lite/prefill_decode_colocation/2a2f_graph_dbo_dp1tp2.sh:16}}, {{cite recipe/gpu/P2pNcclAFDConnector/deepseek_v2_lite/prefill_decode_colocation/2a2f_graph_dbo_dp1tp2.sh:31}}).

 What changes between the attention and FFN serve commands?

The GPUs (0,1 vs 2,3) and the role (attention vs ffn); the rest of the afd block is the same ({{cite recipe/gpu/P2pNcclAFDConnector/deepseek_v2_lite/prefill_decode_colocation/2a2f_graph_dbo_dp1tp2.sh:13}}, {{cite recipe/gpu/P2pNcclAFDConnector/deepseek_v2_lite/prefill_decode_colocation/2a2f_graph_dbo_dp1tp2.sh:40}}).

 Why does the recipe set VLLM_USE_V2_MODEL_RUNNER=1 if vLLM picks V2 by default?

To be explicit. vLLM picks V2 by default when the variable is unset ({{cite vllm:vllm/config/vllm.py:692-694}}), and AFD requires the V2 runner ({{cite afd_plugin/validation.py:90-91}}).

 The recipe turns on DBO with thresholds 2 and 12. What constraint must the run then meet?

Exactly two microbatches. AFD raises when DBO or ubatching is on and num_ubatches != 2 ({{cite afd_plugin/validation.py:126-131}}).

 Which two flags switch this recipe from eager to graph, and which graph mode do they set?

--max-cudagraph-capture-size 64 and --compilation-config with cudagraph_mode: FULL_DECODE_ONLY ({{cite recipe/gpu/P2pNcclAFDConnector/deepseek_v2_lite/prefill_decode_colocation/2a2f_graph_dbo_dp1tp2.sh:26-28}}). GPU AFD allows only that mode ({{cite afd_plugin/v1/worker/cuda_graph.py:20-21}}).
