Purpose

These three files add the connector and control plane to the attention side without rewriting native vLLM. The concept behind them is on {{link concepts/attention-runtime}}; this page maps the files.

Where it sits

Who calls it

The AFD config patch rewrites worker_cls to AFDAttentionWorker when the role is attention ({{cite afd_plugin/validation.py:280-291}}). vLLM then builds this worker like any other. The worker builds the runner inside init_device.

What it calls

The worker delegates device setup to native Worker.init_device, which local-imports and builds GPUModelRunner ({{cite vllm:vllm/v1/worker/gpu_worker.py:469-482}}). The runner builds the connector through the factory ({{cite afd_plugin/connectors/factory.py:49-68}}) and reads the model wrapper.

Walk through the main methods

AFDAttentionWorker.init_device: swap the runner class

vLLM 0.30.0 builds its runner from a module symbol inside Worker.init_device, with no injection hook. The worker replaces that symbol for the native construction window, then restores it ({{cite afd_plugin/v1/worker/attention_worker.py:60-90}}).

  1. Line 82. Save the native runner class.
  2. Line 83. Point the module symbol at AFDAttentionModelRunnerV2.
  3. Line 85. Native init_device local-imports and builds the runner, now the AFD class.
  4. Lines 86-87. Restore the native class in a finally, so the patch is scoped to the window.

Before the swap, the worker asserts the AFD stack and validates the V2 config ({{cite afd_plugin/v1/worker/attention_worker.py:64-73}}).

execute_model: scope the context, then delegate

The runner adds nothing to the forward itself. It opens the AFD context and calls super ({{cite afd_plugin/v1/worker/attention_model_runner_v2.py:580-595}}).

send_dp_metadata: publish one control payload

The mixin builds one payload with the per-stage DP metadata and the graph flags, updates the connector state, then sends ({{cite afd_plugin/v1/worker/attention_metadata.py:75-116}}).

  1. Lines 108-114. Build the AFDControlPayload with the DP metadata and the warm-up/capture/replay flags.
  2. Line 115. update_state_from_dp_metadata pre-allocates the wire buffers.
  3. Line 116. send_dp_metadata_list sends on the designated sender ranks.

How does the worker install the AFD runner?

It replaces the module GPUModelRunner symbol around super().init_device(), then restores it ({{cite afd_plugin/v1/worker/attention_worker.py:82-87}}).

 Which class holds the control-plane publish logic, and why is it a mixin?

AFDMetadataProviderMixin ({{cite afd_plugin/v1/worker/attention_metadata.py:21}}). It is a mixin so the GPU V2 runner and the NPU runners share one implementation ({{cite afd_plugin/v1/worker/attention_metadata.py:21-28}}).

 Why does the module-symbol swap in init_device work at all?

Because native Worker.init_device local-imports GPUModelRunner from the module just before it constructs the runner, so the attribute swap is seen at construction ({{cite vllm:vllm/v1/worker/gpu_worker.py:469-482}}, {{cite afd_plugin/v1/worker/attention_worker.py:82-87}}).
