Where it sits

Who calls it

The plugin registers AFDDeepseekV2ForCausalLM under the model name AFDDeepseekV2ForCausalLM ({{cite afd_plugin/__init__.py:100-102}}, {{cite afd_plugin/__init__.py:213-214}}). The worker selects the AFD model identity before loading ({{cite afd_plugin/v1/worker/attention_worker.py:75-80}}), so vLLM loads this class.

What it calls

The classes subclass native vLLM DeepSeek modules imported as native ({{cite afd_plugin/model_executor/models/deepseek_v2.py:22}}). The proxy calls the connector through the AFD forward metadata, and the DBO yield op between send and receive ({{cite afd_plugin/model_executor/models/deepseek_v2.py:146-158}}).

The layer's compute methods, by role

The layer has no single forward: the runner calls role-specific compute methods. On the attention role, compute_attn_output runs the input norm, attention and post-attention norm, and (on NPU) the gate ({{cite afd_plugin/model_executor/models/deepseek_v2.py:577-647}}). The mlp module then sends the hidden states through the connector.

On the FFN role, the runner calls compute_ffn_output for a dense or gate-on-FFN layer, or compute_experts_output for an attention-side-gate MoE layer ({{cite afd_plugin/model_executor/models/deepseek_v2.py:649-721}}).

The model and causal-LM wrappers

AFDDeepseekV2Model is decorated with support_torch_compile and builds the layers with the role-aware constructor ({{cite afd_plugin/model_executor/models/deepseek_v2.py:724-725}}, {{cite afd_plugin/model_executor/models/deepseek_v2.py:791-802}}). It forwards to the native model, except for the async NPU connector, which uses its own forward ({{cite afd_plugin/model_executor/models/deepseek_v2.py:839-863}}).

AFDDeepseekV2ForCausalLM filters the weight stream by role before the native loader ({{cite afd_plugin/model_executor/models/deepseek_v2.py:964-974}}). The DeepSeek, V3 and GLM-MoE-DSA classes are thin subclasses ({{cite afd_plugin/model_executor/models/deepseek_v2.py:977-986}}).

get_experts_layer_indices and get_experts_routing_spec

The FFN runner needs to know which layers hold experts, and the routing spec for graph capture. get_experts_layer_indices returns the MoE-layer indices ({{cite afd_plugin/model_executor/models/deepseek_v2.py:887-895}}).

  1. Lines 887-895. Collect every AFDDeepseekV2DecoderLayer whose is_moe_layer is true.
  2. Lines 897-907. Return the router-logits width and dtype, so graph capture can pre-allocate the wire buffers.

The causal-LM class forwards both to the model ({{cite afd_plugin/model_executor/models/deepseek_v2.py:955-962}}).

The shell computes the gate before transport only when it owns one; a gate-less shell keeps the native delegation ({{cite afd_plugin/model_executor/models/deepseek_v2.py:347-371}}).

_checkpoint_weight_roles decides each weight's owner ({{cite afd_plugin/model_executor/models/deepseek_v2.py:69-95}}). A non-layer path (embeddings, final norm) returns both roles; a self_attn path returns attention; a dense mlp path follows the gate flag; a MoE gate path returns both roles when the gate runs on the attention side, and the other expert weights return the FFN role. The causal-LM class passes the connector choice so the async NPU connector can also keep the shared-expert weights on the attention role ({{cite afd_plugin/model_executor/models/deepseek_v2.py:969-973}}).

What base class does AFDDeepseekV2RemoteExpertsMoE extend?

The native DeepseekV2MoE; it keeps the native MoE forward but replaces the experts with a proxy ({{cite afd_plugin/model_executor/models/deepseek_v2.py:277}}).

 The decoder layer has no single forward. Which methods run its two halves, and on which role?

compute_attn_output on the attention role ({{cite afd_plugin/model_executor/models/deepseek_v2.py:577-647}}); compute_ffn_output or compute_experts_output on the FFN role ({{cite afd_plugin/model_executor/models/deepseek_v2.py:649-721}}).

 Why does get_experts_routing_spec exist, and what does it return?

Graph capture must pre-allocate the router-logits buffer, so it needs a static shape. It returns the router-logits width (the routed-expert count) and dtype ({{cite afd_plugin/model_executor/models/deepseek_v2.py:897-907}}).
